val library_name : string option Stdlib.ref

Name of the dune library whose module is being preprocessed, from the library-name cookie dune passes to every ppx driver it runs on a library's sources (--cookie 'library-name="foo"'). None when the file is not part of a library (an executable or test stanza) or when the driver is run outside dune.

val module_path_of_loc : Ppxlib.location -> string list

The OCaml path under which the module being preprocessed is reachable from a consumer, e.g. ["Sarek_stdlib"; "Float32"] for sarek/Sarek_stdlib/Float32.ml. Both registries key the intrinsic on it, and the kernel PPX emits it verbatim as the existence witness and as the Native backend's call target, so it must be the REAL path.

It comes from the library name dune hands the driver, under dune's default (wrapped true): module M of library lib is Lib.M, and the library's main module lib.ml is Lib itself. Outside a library it is [M].

It used to be guessed from the source DIRECTORY: a directory name containing an underscore was taken to be the library name, any other was dropped. That held for sarek's own trees, whose directories are named after their libraries, and nowhere else: a downstream library foo_intrinsics living in src/intrinsics/ registered Bits.f instead of Foo_intrinsics.Bits.f, and renaming the directory changed the path.

A (wrapped false) library is not detectable from the driver: its modules are top-level, but the path computed here still carries the library prefix, and the witness then fails to compile ("Unbound module"), loudly. Declare intrinsics in a wrapped library.

val size_of_type_name : loc:Ppxlib.Location.t -> string -> int

Derive the size (in bytes) of a sarek type from its name alone. This avoids the Ctypes dependency for the pure metadata path. Sizes match the Ctypes.sizeof values for the corresponding C types: float32=4, float64=8, int32=4, int64=8, bool=4, char=1, int=4 (GPU int).

val expand_sarek_intrinsic_type : ctxt:Ppxlib.Expansion_context.Extension.t -> Ppxlib.payload -> Ppxlib_ast.Ast.structure_item list

Extension for type%%sarek_intrinsic - handles type registration. The ctype field is OPTIONAL.

  • When present: emits both Sarek_registry (JIT/FFI) and Sarek_ppx_registry registrations using Ctypes.sizeof for the authoritative byte-size.
  • When absent: emits only Sarek_ppx_registry registration using a pure size derived from the type name. No Ctypes dependency.

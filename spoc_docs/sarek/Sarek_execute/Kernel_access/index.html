Module Sarek_execute.Kernel_access

How a kernel uses its vector parameters, and whether it can be fused horizontally (specs/launch-window.md).

Both answers are read from the IR only and are conservative: a use this module cannot classify counts as a read AND a write, and a construct it does not understand makes the kernel non-fusable. Wrong in the other direction would let the launch window reorder or merge launches that conflict.

Horizontal fusability

val rewritten_intrinsics : string list

Position intrinsics that horizontal fusion rewrites, under the exact path Sarek_stdlib.Gpu only. Each rewritten form keeps the type the backends give the original: block_idx_x - off and gdx * block_dim_x stay in the backend's own unsigned type where it has one.

val refused_intrinsics : string list

Position intrinsics a member may not use at all. grid_dim_x would have to become an int parameter, while CUDA/HIP, OpenCL and Metal emit it as an unsigned value, so comparisons and divisions with negative operands would change meaning. block_id_x is an alias the backends accept for block_idx_x; it is refused rather than rewritten under a second name.

Module Sarek_execute.Coopmat_variant

Launch-time variant of a cooperative-matrix kernel on the CUDA backends.

wmma needs a 32-byte aligned address and a stride that is a multiple of 16 bytes, which the IR does not promise. The generators emit the bare instruction for an access they can prove aligned, and for every other access a run-time test with a staging path through a per-warp shared buffer (Sarek_ir_coopmat_align). A kernel whose accesses depend on scalar arguments (a GEMM's k and n) would pay that buffer on every launch, so the host decides instead: Sarek_ir_coopmat_align.derive reduces "every access is aligned" to a predicate on the kernel's int32 parameters, and at launch the actual arguments either satisfy it (the kernel marked with Sarek_ir_coopmat_align.mark_aligned: bare wmma, no check, no buffer) or not (the kernel as given: the staged variant). The marked kernel is a distinct IR value, built once per kernel, so Execute's source memo, which keys on the IR's physical identity, holds one source per variant (and per block) and each is compiled once.

Only the CUDA frameworks are concerned; every other backend, and a kernel with no cooperative-matrix statement, gets the kernel it was given. The base pointers are assumed 32-byte aligned (device allocations).

type outcome =
  1. | Aligned
    (*

    the marked variant: no check, no staging buffer

    *)
  2. | Staged
    (*

    the kernel as given: static proofs where they hold, run-time check and staging for the rest

    *)
  3. | Checked
    (*

    every access tested at run time: a launch argument's base pointer is not 32-byte aligned, which the static proofs assume

    *)
  4. | Not_applicable
    (*

    not a CUDA framework, or no cooperative matrix

    *)

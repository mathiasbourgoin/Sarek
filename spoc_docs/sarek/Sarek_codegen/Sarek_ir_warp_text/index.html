Module Sarek_codegen.Sarek_ir_warp_text

Source-text lowering of the warp operations, shared by the source backends (CUDA C / HIP, OpenCL C, GLSL, MSL, WGSL).

The semantics are those of Sarek_warp: every lane of the warp participates, and the result for lane i is the table of docs/plans/warp-shuffle-intake-2026-10-17.md section 4.3. The vendors differ in what they leave undefined (an out-of-range delta, the high bits of a lane operand), so no backend passes the Sarek operand to a relative shuffle unguarded:

  • CUDA C / HIP clamp an out-of-range delta / mask to 0 (which every native relative shuffle maps to "own value") and use the native __shfl_down / __shfl_up / __shfl_xor / __shfl;
  • OpenCL C, GLSL, MSL and WGSL compute the source lane explicitly from the lane id and the warp width, and call the INDEX shuffle with it. Only the base shuffle extension is then needed (no _relative / _shuffle_up extension, no SHUFFLE_RELATIVE feature bit), and the out-of-range cases are defined by construction.

A shuffle is emitted as a call of a small helper function, defined once per (operation, value type) the kernel uses, so an operand expression is evaluated exactly once. The value type is part of the IR name (Sarek_warp.ir_name), so no backend infers expression types.

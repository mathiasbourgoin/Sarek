Module Sarek_gemm.Coopmat

A tiled f16 GEMM on cooperative-matrix (tensor-core) instructions; see Sarek_gemm_coopmat. Results are bounded, not bit-identical: it needs Sarek_coopmat.accept_relaxed_accumulation before launching.

A tiled f16 GEMM built from cooperative-matrix statements (specs/coopmat-hip-wmma.md).

D = A x B + C for row-major matrices: A is m x k float16, B is k x n float16, C and D are m x n float32. With ~b_layout:Col_major, B is stored transposed (n x k, element (r, c) of B at c * k + r), which is how token-major activations are laid out and what a fragment loads with contiguous reads on HIP gfx11. Each subgroup (wavefront / warp) computes a frag*frags_m x frag*frags_n tile of D (frag is 16 unless given, 8 on Metal), stepping through k frag at a time with one frag x frag x frag multiply-add per fragment pair; a block holds waves subgroups of 32 invocations.

The kernel is IR, not a %kernel: the DSL has no cooperative-matrix surface. It runs where the configuration f16 * f16 + f32 -> f32 is offered — today HIP on gfx11 — and on the interpreter, and in both cases only after Sarek_coopmat.accept_relaxed_accumulation: the matrix unit chooses its addition order, so the result is within gamma_k * (sum |A*B| + |C|) of the exact value (u = 2^-24), not bit-identical to a scalar loop.

val default_tiling : tiling

2x2 fragments (a 32x32 tile) per wave, 2 waves per block: the best single choice across the spoc_llm prefill shapes measured on the RX 7900 XTX (specs/coopmat-hip-wmma.md, Benchmark). It is not the best per shape: at N = 1024 one fragment per wave fills more of the 96 compute units, and at N = 12288 4x2 is faster.

ir ?tiling ?b_layout () is the kernel (a, b, c, d, m, n, k): d = a * b + c. a, b are float16 vectors, c, d float32 vectors, m, n, k int32; b is k x n row-major, or n x k with ~b_layout:Col_major. Launch with launch_dims after check_shape.

run ~device ?tiling ?b_layout ~a ~b ~c ~d ~m ~n ~k () launches ir on device. Raises Invalid_argument on a shape check_shape rejects or a vector shorter than the shape needs, and the launch gate's capability error where the device does not offer the configuration or the program has not called Sarek_coopmat.accept_relaxed_accumulation. Asynchronous like any launch: read d after the usual transfer.

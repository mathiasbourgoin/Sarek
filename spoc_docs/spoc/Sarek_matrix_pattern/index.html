Module Sarek_matrix_pattern

Recognition of matrix-product (GEMM) loop nests in Sarek IR.

A GEMM nest is an accumulator acc (a let mut) updated by a for loop over a reduction variable kv as acc := acc + A[ia] * B[ib] (or fma A[ia] B[ib] acc) and then stored once as C[ic] <- e(acc), where the three indices are affine (Sarek_ir_affine) and separate into a row index M (in A and C), a column index N (in B and C), kv (in A and B) and optional batch indices (in C, and in A or B or both). The full pattern and every rejection are specified in specs/matrix-pattern-advice.md.

This module only recognises. Sarek_matrix_advice says which matrix-unit configuration applies; the PPX turns that into a compile-time alert; and Sarek_fusion uses it to explain why a GEMM operand is not fused.

Scope: the kernel body only, not helper functions. An accumulation written directly into memory (c.(i) <- c.(i) + a * b in the loop) is not a candidate.

type layout = Sarek_coopmat_types.layout =
  1. | Row_major
  2. | Col_major

How an operand is laid out in memory, from its two strides: row-major when the column stride is 1, column-major when the row stride is 1. Any other operand (no unit stride, equal strides, overlapping rows) is not a GEMM operand: a matrix unit loads a tile with one base and one leading dimension.

type operand = Sarek_matrix_pattern_types.operand = {
  1. array : string;
  2. elt : Sarek_ir_types.elttype;
  3. index : Sarek_ir_types.expr;
  4. row_stride : Sarek_ir_types.expr;
  5. col_stride : Sarek_ir_types.expr;
  6. layout : layout;
  7. offset : Sarek_ir_types.expr;
}

One matrix of C = A × B. Rows and columns are those of the matrix: A is M × K, B is K × N, C is M × N. The strides are uniform expressions; offset is everything in the index that is neither the row nor the column term (constants and batch terms). index is the let-inlined index.

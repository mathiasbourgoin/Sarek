Module Sarek_vulkan.Vulkan_api_transfer

Ranged host<->device copies (specs/vulkan-async-api.md).

Every copy completes before it returns. It first completes the device's pending launches (Vulkan_api_device.drain_pending), so it never lands under a kernel still using the buffer and always sees what a kernel wrote; a copy issued before a launch is visible to it (the launch is recorded after the copy has finished).

Three paths, by where the host bytes and the device bytes live:

  • the host range lies inside an import (Vulkan_api_host) and the host cannot access the device buffer at memory speed (unmapped, or uncached for reads), or a write of at least dma_min_bytes: one vkCmdCopyBuffer straight between the import and the device buffer (DMA, no staging, no host memcpy);
  • the device buffer is host-mapped and the host side may touch it (mapped_cached for reads: uncached BAR memory reads at ~0.03 GB/s): one memcpy at the byte offset;
  • otherwise: a staging buffer of exactly the range, one memcpy and one vkCmdCopyBuffer; read-back staging is HOST_CACHED when available.

val dma_min_bytes : int

Host-to-device into a MAPPED buffer from a pinned range: below this many bytes a memcpy beats the submission and fence wait of a DMA copy (4 MiB: 19.0 vs 16.7 GB/s; 16 MiB: 19.0 vs 21.6 GB/s; RX 7900 XTX, H7 bench).

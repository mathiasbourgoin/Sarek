Module Sarek_vulkan.Vulkan_api_host

Pinned and registered host memory (specs/vulkan-async-api.md).

Two sources of a host range that a VkBuffer covers:

  • alloc_pinned: memory the driver allocates (vkAllocateMemory from a HOST_VISIBLE | HOST_COHERENT type, HOST_CACHED when there is one), mapped once for the life of the block. The mapped pointer is the pinned address. No host page reaches the driver, so there is no userptr object and no kernel invalidation callback (the Sarek #503 path), and no extension is needed.
  • register: the pages of a caller's range imported into the driver as device memory (VK_EXT_external_memory_host). The import covers whole pages: the range rounded outwards to the device's minImportedHostPointerAlignment. Opt-in, and refused on AMD drivers (Vulkan_host_import_policy); a device without the extension refuses it.

A copy between such a range and a device buffer is one vkCmdCopyBuffer with no staging buffer and no host memcpy: the DMA engine reads or writes the host pages. A copy whose host range lies inside a buffer's range uses it, whether or not it names the allocated or registered bytes exactly.

The memory type for a pinned block, best first: HOST_VISIBLE | HOST_COHERENT | HOST_CACHED, then without HOST_CACHED, both not DEVICE_LOCAL; only then the DEVICE_LOCAL ones. On a discrete GPU the DEVICE_LOCAL host-visible type is the BAR window onto VRAM, write-combined and read at 0.03 GB/s; a UMA device has only DEVICE_LOCAL types.

val free_pinned : Device.t -> nativeint -> unit

Releases the block's buffer and memory, which unmaps it. A block whose device was destroyed has nothing left to release. The table is keyed by address, as core's is: if the address was handed out again after the device was destroyed, a late free of the old block cannot be told from a free of the new one. Free every block before destroying its device.

# SPOC/Sarek Knowledge Base — Index

Canonical entry point for the project KB. Full overview + Component Inventory: [README.md](README.md).

> Layout note: this KB is organized as `README.md` (overview/map) + per-area folders,
> with two canonical top-level files beside them. Roster KB hooks should treat
> **this file** (or `README.md`) as the index.

## Canonical files

- [properties.md](properties.md) — invariants. Its fenced `code-intel` block is
  **executed** by `scripts/check-kb-properties.sh` on every CI run; the prose sections
  are not. Leads with the `gate-vacuous` catalogue, which is the most expensive thing
  this campaign has learned.
- [glossary.md](glossary.md) — a pointer index over the evidence tiers, the capability
  kinds, the f16 regimes and model set, and the process class vocabulary. Not a source of
  truth: when it disagrees with the document it points at, the document wins.

**`spec.md` and `architecture.md` are deliberately absent** (backlog-100). There is no
whole-project specification to record — writing one would be invention, and an invented
spec is worse than none because `spec-compliance-auditor` would then audit against it.
`architecture.md` would duplicate [README.md](README.md), which already *is* the
component inventory; a second copy rots against the first. Both stay unwritten until
something real needs them. `spec-compliance-auditor` correctly exits 0 with no
`kb/spec.md`, and `code-quality-auditor` reads `architecture.md` only if present.

**`skills-meta/` is not tracked** and is not part of this KB. It is session telemetry —
verbatim operator messages with transcript line numbers, and self-assessments written to
be blunt rather than published — and it says nothing about SPOC or Sarek. Its durable
content was lifted into `properties.md` and `glossary.md`; the reasoning is recorded in
`.gitignore`.

Module Sarek.Sarek_cpu_runtime_warp

Warp shuffles for the Native backend: the slow, sequential, correct version.

A warp is simulated: Sarek_warp.simulated_width () consecutive threads of the block (linear thread id, x fastest). A shuffle is one exchange through a per-block typed array held in the block's shared memory:

  1. each thread publishes its value at its linear thread id;
  2. block barrier (every thread of the block reaches the call, which the convergence rule guarantees);
  3. each thread reads the slot of its source lane, from Sarek_warp.source_lane;
  4. a second barrier, so a following shuffle cannot overwrite a slot that a slower thread has not read yet.

The exchange arrays are typed (int32 array, float array); there is no Obj. The cost is two barriers per call and one slot per thread of the block: this is the correctness oracle, not a fast path.

type op = Sarek_warp.op =
  1. | Idx
  2. | Down
  3. | Up
  4. | Xor

The four shuffle flavours, re-exported so generated kernels name them without depending on the IR library.

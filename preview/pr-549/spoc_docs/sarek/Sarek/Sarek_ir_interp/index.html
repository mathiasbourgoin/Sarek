Whether two vectors are the same vector.

Physical identity, taken on the vector's own device_buffers table: it is allocated once per vector and never replaced, it has one type whatever the vectors' element types (so two vectors of different types can be compared without Obj), and a comparison of the records themselves would need both to have the same type. The vector id is deliberately NOT used: ids come from a non-atomic counter and can collide across domains (R-1).

val bind_vector : writeback list Stdlib.ref -> ('a, 'b) Spoc_core.Vector.t -> to_array:(('a, 'b) Spoc_core.Vector.t -> value array) -> value array

The value array bound to vec: the one already bound among writebacks if vec is a vector passed before, otherwise a fresh one from to_array, which is recorded in writebacks.

Two kernel parameters bound to the same vector must share ONE value array: a private copy each would make a write through one invisible to a read through the other, and the writebacks would then overwrite each other in an order that depends on the entry point. Binding by identity gives the semantics of the device, where both parameters are the same buffer.

Whether two EXEC_VECTOR wrappers stand for the same vector.

Their underlying values can only be compared once their types are known to be equal, which the type ids witness. Execute.exec_arg_of_vector gives every wrapper of a Vector.t the SAME stable underlying_type_id (per element kind) and underlying = v, so two arguments that are one vector compare physically equal. A wrapper that mints a fresh id per instance (the interpreter plugin's own buffer wrapper) never matches: it wraps a device buffer, not a host vector, and no launch built from host vectors reaches it.

Module Sarek_ir_coopmat_align

Static alignment proof for cooperative-matrix loads and stores on NVIDIA (wmma), shared by the CUDA/C and PTX generators.

wmma.load / wmma.store need a 32-byte aligned address and a leading dimension that is a multiple of 16 bytes. The IR promises neither (any start index, any stride: Sarek_ir_types.coopmat_op.CM_load), so a generator either checks at run time and stages a misaligned tile through shared memory, or proves the access aligned and emits the bare instruction. This module is the proof.

What is proved. A power-of-two factor of an int32 expression: f such that f divides the expression's value, whatever the run. It is computed from the expression alone, by rules that hold under wrapping 32-bit arithmetic (divisibility by a power of two is preserved modulo 2^32):

  • an integer constant c: its lowest set bit (0: unbounded);
  • a + b, a - b: the minimum of the factors;
  • a * b: the product;
  • a << c with a constant c: the factor of a times 2^c;
  • a variable bound by an immutable let: the factor of its definition;
  • anything else (kernel parameters, loop variables, mutable variables, division, intrinsics, array reads): 1.

An access is proven when factor index * element bytes >= 32 and factor stride * element bytes >= 16 (both sides are powers of two, so >= is divisibility). The base pointer is assumed aligned: a global buffer is a device allocation (256-byte aligned) and a .shared array a cooperative-matrix statement accesses is declared 32-byte aligned by the generators. A cooperative-matrix kernel that does not rely on either (a pointer into the middle of an allocation) must not pass a view to the launch.

The walk is by name with lexical scoping, so a shadowing binder (a let, a for variable, a match payload) hides an outer fact. The result is the list of proven operations, identified physically: a generator asks about the very node it is about to emit, and an operation it cannot find (a rewritten tree, a helper body) is unproven, which is the safe answer.

Launch-time variant: a predicate over the scalar arguments

An access whose index or stride depends on a kernel parameter (a GEMM's k and n) cannot be proven aligned from the IR alone, but the host knows the parameter's value at launch. derive reduces "every cooperative-matrix access of the kernel is aligned" to a condition on the kernel's scalar int32 parameters, a disjunction of conjunctions of atoms "parameter p is a multiple of n" (a predicate). The launch evaluates it (holds) on the actual arguments: true selects the variant of the kernel generated with mark_aligned (bare wmma, no check, no buffer), false the staged variant.

need env e n is the condition under which e is a multiple of n (a power of two), by the rules of factor extended with parameters as atoms, and with a product a * b allowed any split a multiple of x, b multiple of n / x. A kernel parameter that is not shadowed is the atom (name, n); anything the rules cannot reduce makes the condition false and derive answer None (the kernel always takes the staged variant).

  1. | Multiple of string * int

  2. | At_least of string * int

    |parameter| >= n: a store whose stride is below the tile edge overlaps its own rows, and is not left to the matrix unit

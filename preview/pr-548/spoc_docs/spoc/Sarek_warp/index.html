Module Sarek_warp

Sarek_warp - the one definition of warp shuffle semantics.

The four shuffle primitives (warp_shuffle, warp_shuffle_down, warp_shuffle_up, warp_shuffle_xor) and the two warp introspection constants (warp_size, lane_id) reach the IR as EIntrinsic nodes. The shuffles are TYPED in the IR: the front end appends the value type to the name (warp_shuffle_down_f32) so a backend never has to infer the type of an expression to choose a spelling.

Contract (docs/plans/warp-shuffle-intake-2026-10-17.md, section 4.3), for lane i of a warp of width W (a power of two) and operand x read as a two's-complement int32:

  • warp_shuffle v x: source lane x land (W-1);
  • warp_shuffle_down v d: i + d, or i when d < 0 or i + d >= W;
  • warp_shuffle_up v d: i - d, or i when d < 0 or i - d < 0;
  • warp_shuffle_xor v m: i lxor m, or i when m < 0 or i lxor m >= W.

source_lane is that table, executable. Native and the interpreter use it directly; the source backends emit equivalent guards, and the parity tests compare every backend with it.

Simulated warp width

Native and the interpreter have no hardware warp. They simulate one of simulated_width () lanes (default 32, the width of the CUDA and Apple devices and of RDNA). The width is a launch-time parameter in the sense that it is read at each launch; with_width is the test hook that lets the parity tests run the simulation at a GPU's width.
